# A coding agent's CLI as a Provider runs with no tools and nothing of the user's setup

A user who already pays for a coding agent's plan (ChatGPT through Codex, GitHub Copilot, Claude through Claude Code, OpenCode Go or another plan signed in through OpenCode, or through Pi) can have that agent write the Summary: Takku runs the user's own installed and signed-in CLI, one run per request, through the same Chat Completions client as every Provider (ADR 0004, ADR 0013). Takku holds no key and offers no sign-in. The promise is "the plan you already pay for": a user with an API key already has the OpenAI-compatible Profiles. These are Providers like the others, with no term of their own, offered quietly like any Provider of the user's own (as Mistral is), not promoted over Takku Credit; where the text goes is the user's choice (ADR 0001).

An agent is not a chat model: it has tools and the user's setup. A run therefore gets none of them: no shell, file reading or any other tool, no instructions (AGENTS.md and the like), settings, MCP servers, plugins, hooks or memories, no session kept, in an empty folder. A Transcript is text written by other people: with tools, a sentence said in a meeting could make the agent run a command or read a file, and a memory or a plugin could copy parts of a meeting elsewhere. In the prototype Copilot ran `ls` and `cat` unasked until its tools were really removed.

This is a rule, not a default: a CLI that cannot run this way is not offered, and there is no option to bring the user's setup back.

## Consequences

- A run gets no API key variables from Takku's environment (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `CODEX_API_KEY`, GitHub tokens and the like): a CLI that finds one uses it instead of the plan (Claude Code always does under `-p`), and the user would pay per token without knowing.
- The agent's own system prompt is replaced by Takku's where the CLI allows it: kept, it makes the model write tool calls as text even with no tools to call.
- Each CLI needs its own flags to get there, and they are easy to get wrong (Copilot's empty `--available-tools` keeps every tool). They are checked with a real run, not read from the help, and checked again before every Takku release (`docs/TESTING.md`): these CLIs update themselves. When a CLI changes under Takku, its error reaches the user as the CLI wrote it; Takku does not pin or check versions.
- OpenCode (v2) is the one exception to "no session kept": it keeps the sign-in in the same database as its sessions, so a run apart from that database has no sign-in, and every run saves a session there. Takku deletes the session after the run, and before each run any session of its own agent left by an earlier one. If the run is cut short (Takku quits, the Mac sleeps) a session with a part of the meeting stays in OpenCode until the next run; the documentation says so. The alternatives were worse: leaving OpenCode out, or having Takku read the user's key with `opencode auth export`, which would make Takku hold a key.
- Pi reads its settings file, which sits next to its sign-in (`~/.pi/agent`): moving its folder would leave it signed out, and copying the sign-in would make Takku hold a key and could leave Pi's own copy with a spent token. Its flags turn off what in its setup could act or see the meeting (tools, extensions, skills, prompt templates, context files, sessions); what the settings still choose, the model and the thinking level, Takku always names, so Pi has no *Default* model, and *Model default* reasoning is Pi's, from those settings.
- Claude Code is offered although Anthropic's terms are not clear on it: they forbid third-party apps offering Claude.ai sign-in and automated access without an API key "except where we otherwise explicitly permit it", and `claude -p` with a plan is documented. Takku offers no sign-in and runs the user's own, unmodified CLI, as other apps do (Paseo, T3 Code). The risk is to the user's account; if Anthropic forbids it explicitly, the Profile goes.
